# corne-layouts

Vial layouts for a 46-key Corne V4.1, managed as plain-text Markdown instead
of hand-edited JSON. See `README.md` for the full workflow and grid format.

**The one rule:** only edit files in `layouts/*.md`. Everything under `dist/`
is generated by `npm run build` and must never be hand-edited — except
`dist/default.vil`, the vendor's factory dump, which is read-only and
enforced by CI (`.github/workflows/protect-default-layout.yml`).

## Verification

This repo has no test framework or linter — `layouts/*.md` parsing is its
own correctness check. Run both of these before considering a change done:

```
npm run build
npm run format
```

- `npm run build` parses every `layouts/*.md` (except `default`) and writes
  the matching `dist/*.vil`. A parse error (bad keycode label, malformed
  grid, missing Settings row, etc.) makes it exit non-zero — that failure
  *is* the test suite.
- `npm run format` re-renders each `layouts/*.md` from its own parsed
  content. Run it after hand-editing a layout file and check `git diff` —
  any change beyond column alignment means the edit didn't round-trip
  cleanly (e.g. a keycode label that doesn't parse back to what was typed).

## Focused Verification

There's no per-file test runner to filter to — `npm run build` and
`npm run format` already run in a couple of seconds over every layout file,
so there's nothing narrower to scope down to. For a change confined to one
`layouts/<name>.md`, the fast targeted check is to build and look only at
that file's output diff:

```
npm run build && git diff --stat dist/<name>.vil
```
